## Local Setup

### 1. Backend

```bash
cd backend
python -m venv .venv
# Windows:
.venv\Scripts\activate
# macOS/Linux:
source .venv/bin/activate

pip install -r requirements.txt
```

**`requirements.txt`** (key packages):
```
fastapi
uvicorn[standard]
faster-whisper
pyannote.audio
google-generativeai
aiosqlite
python-multipart
python-dotenv
```

Create `backend/.env`:
```env
HUGGINGFACE_TOKEN=hf_your_token_here
GOOGLE_API_KEY=your_google_ai_studio_key_here
AUDIO_STORAGE_PATH=./audio_files
MAX_UPLOAD_BYTES=26214400
LOW_CONFIDENCE_THRESHOLD=0.5
WHISPER_MODEL_SIZE=small
```

First run (downloads models, ~500 MB for `small`):
```bash
uvicorn app.main:app --reload --port 8000
```

Verify: `GET http://localhost:8000/health` → `{ "status": "ok" }`

---

### 2. Frontend

```bash
cd frontend
npm install
```

Create `frontend/.env.local`:
```env
NEXT_PUBLIC_API_URL=http://localhost:8000
```

```bash
npm run dev
```

Open `http://localhost:3000`

## Validation Scenarios

### V-01: File Upload Validation

**Goal**: Confirm unsupported/oversized files are rejected before processing (FR-005, SC-004).

1. Visit `http://localhost:3000`
2. Click "Upload" and select a `.txt` file
3. **Expected**: Error message "Unsupported file type. Supported formats: WAV, MP3, M4A, WEBM, OGG"
4. Select a WAV file larger than `MAX_UPLOAD_BYTES`
5. **Expected**: Error message "File too large. Maximum size is 25 MB"

---

### V-02: Consent Gate

**Goal**: Confirm processing cannot start without consent (FR-003, SC-006).

1. Visit `http://localhost:3000`
2. Click "Upload" and select a valid audio file
3. **Expected**: Consent modal appears before upload proceeds
4. Click "Cancel"
5. **Expected**: Upload aborted, no conversation created
6. Repeat, click "I consent"
7. **Expected**: Upload begins; conversation record created

---

### V-03: End-to-End Processing (2-speaker, 10 seconds)

**Goal**: Confirm the full pipeline runs for a short file (SC-001).

1. Upload `tests/fixtures/two_speakers_10s.wav` with speaker count = 2
2. **Expected**: Pipeline progress steps visible in order: Uploading → Transcribing → Diarizing → Analyzing → Summarizing → Complete
3. Navigate to Results → Transcript tab
4. **Expected**: Segments shown with "Speaker 1" / "Speaker 2" labels, timestamps, and per-speaker colors

---

### V-04: Speaker Rename Propagation

**Goal**: Confirm rename updates all views within 1 second (SC-002).

1. From the Results page, click "Speaker 1" label
2. Enter "Rahul" and confirm
3. **Expected**: "Rahul" appears immediately in Transcript, Timeline, Analytics, and Summary tabs
4. **Expected**: No page reload occurs

---

### V-05: Analytics Display

**Goal**: Confirm talk-time and turn metrics are displayed.

1. Open a processed conversation
2. Navigate to Analytics tab
3. **Expected**: Bar chart shows talk-time % per speaker; table shows turn count, avg turn length, interruptions per speaker

---

### V-06: Summary & Manual Regeneration

**Goal**: Confirm summary is generated and the "Regenerate Summary" button appears after text edits (FR-028, Q3).

1. Open a processed conversation → Summary tab
2. **Expected**: Overview, key points, decisions, action items displayed
3. Navigate to Transcript tab → edit one segment's text
4. Navigate back to Summary tab
5. **Expected**: "Regenerate Summary" button visible
6. Click it
7. **Expected**: Summary refreshes using updated transcript

---

### V-07: History and Full Delete

**Goal**: Confirm conversations persist and full delete removes all data (SC-008).

1. Process a conversation, close browser, reopen `http://localhost:3000`
2. Navigate to History
3. **Expected**: Previous conversation listed
4. Select it → Delete → confirm
5. **Expected**: Conversation removed from list
6. Verify in `backend/audio_files/`: audio file no longer present
7. Verify in SQLite: no rows for that `conversation_id`

---

### V-08: Service Unavailable Offline Mode (Q4)

**Goal**: Confirm existing conversations are accessible when the backend is down.

1. Process and complete at least one conversation
2. Stop the backend (`Ctrl+C` on uvicorn)
3. Reload the frontend
4. **Expected**: A banner "Processing unavailable — service is unreachable" appears
5. **Expected**: History page and existing conversation results remain fully accessible

---

### V-09: Partial Pipeline Failure Recovery

**Goal**: Confirm retry is offered when a pipeline step fails (FR-027).

1. Set `GOOGLE_API_KEY=invalid_key` in `backend/.env` and restart the backend
2. Upload and process a short audio file
3. **Expected**: Pipeline reaches Summarizing → fails with "Service unavailable"
4. **Expected**: Transcript and Analytics tabs still show results from completed steps
5. **Expected**: A "Retry Summarizing" button appears
6. Restore a valid key → click Retry
7. **Expected**: Summarizing step completes successfully

---

## Google Colab Fallback

For heavy processing (long audio, slow CPU):

1. Open `colab_runner.ipynb` in Google Colab
2. Run all cells — installs deps, starts uvicorn, exposes ngrok URL
3. Copy the ngrok URL (e.g., `https://abc123.ngrok-free.app`)
4. Set `NEXT_PUBLIC_API_URL=https://abc123.ngrok-free.app` in `frontend/.env.local`
5. Restart `npm run dev`
6. The frontend now sends audio to Colab for processing

> **Note**: ngrok free tier provides 1 concurrent tunnel. Restart the notebook cell to get a fresh URL if the tunnel expires.
